The evidence-pipeline hazard, demonstrated (old script NOT run)
------------------------------------------------------------------
The old script picks a run directory independently per variable with
    sorted(glob(f"{ROOT}/{run}/output_0*/{name}_1h_inst.nc"))[-1]
For run="v3_upd_default" today, that glob resolves to:

  output_0000/ta_1h_inst.nc
  output_0001/ta_1h_inst.nc
  output_0002/ta_1h_inst.nc
  output_0003/ta_1h_inst.nc

sorted(...)[-1] picks output_0003 -- not output_0002, the directory E73 was
actually computed from. output_0003's provenance.txt names commit
e71430fbfbab06a36903aab4da8a37ed4c762d4a, a different code version than
846ef55d (E73's commit). Anyone re-running the old script today with
`v3_upd_default` as the bare run name, intending to reproduce E73, would
silently get output_0003 against a different commit instead, with no
warning that the code version had changed. This is exactly the flaw
described in "New insight D": explicit output_XXXX directories (which
compare_runs.py requires, and output_active/bare run roots it refuses) are
the fix.

compare_runs.py's --reference/--run flags require an explicit output_XXXX
directory for this reason; this reproduction used output_0002 explicitly,
not "v3_upd_default" or "output_active".
